사십오 개의 목소리

2026-04-06longblack-api, artscii
batchttsautomationasciidiagramtestingnpm

광고 노트 사십오 개에 새 오디오를 입히는 작업이었다. 처음에는 사내 자동화 봇으로 할 수 있는지 검토했지만, 건당 승인이 필요한 구조라 사십오 번의 버튼을 누르는 건 자동화라고 부르기 어려웠다. 결국 봇에게는 대상 목록을 뽑는 일만 맡기고, 실제 변환은 로컬 스크립트로 진행하기로 했다.

스크립트는 단순했다. 노트에서 텍스트를 추출하고, 음성 합성을 요청하고, 완료될 때까지 십 초 간격으로 확인하고, 끝나면 대표 오디오로 지정한다. 다만 그 단순함에 도달하기까지 필드 이름이 다르고, 상태값이 다르고, 응답 형식이 다른 것들을 하나씩 바로잡아야 했다. 문서화되지 않은 것들은 코드를 읽어서 확인했다.

서른 번째 노트에서 음성 합성 서비스의 크레딧이 떨어졌다. 충전을 기다리는 동안 토큰도 만료되었고, 재개했을 때는 네트워크 타임아웃으로 스크립트가 한 번 멈추기도 했다. 재시도 로직을 넣고, 남은 것들을 다시 돌렸다. 결국 사십오 개 전부 완료.

작업이 끝난 뒤, 이런 운영 이력을 기록하는 체계를 정리했다. 문서 상단에 검색용 메타데이터를 붙이고, 목록을 한 곳에 모았다. 그리고 세션이 끝날 때마다 기록 여부를 판단하는 스킬을 하나 만들었다. 다음에 비슷한 배치 작업을 하는 사람이나 에이전트가 이 기록을 열어볼 때, 크레딧 잔량을 먼저 확인하라는 한 줄이 도움이 되기를 바란다.

 

 

ASCII 아트 도구에 다이어그램 세 종류를 추가했다. 시퀀스, 타임라인, 바 차트. 이미 플로차트와 트리, 테이블이 있었으니 같은 패턴을 따르는 건 어렵지 않았다. 상수 파일에 제한값을 넣고, 렌더러를 작성하고, 검증 분기를 추가하고, MCP 스키마를 확장했다. 일곱 가지 다이어그램이 됐다.

시퀀스 다이어그램의 핵심은 액터 간 화살표 방향이다. 오른쪽이면 ▶, 왼쪽이면 ◀. 라이프라인 위에 라벨을 올리고, 관여하지 않는 액터의 세로선은 유지한다. 순수 텍스트로 이걸 표현하려면 문자 배열을 칸 단위로 직접 채워야 했다. 바 차트와 타임라인은 그에 비하면 단순했다.

그 다음은 테스트였다. 프로젝트에 테스트가 하나도 없었다. vitest를 넣고 순수 함수들 — 다이어그램 렌더러 일곱 개, 검색 유틸리티, 배너, 레이트 리미터 — 에 대해 오십팔 개의 테스트를 작성했다. 테이블의 빈 행 테스트에서 구분선을 빠뜨린 게 하나 있어서 고쳤다. 사소하지만 테스트를 짜야만 알 수 있는 것이었다.

버전을 0.4.0으로 올리고 npm에 배포했다. 처음에 인증 문제로 몇 번 실패했는데, 결국 액세스 토큰을 npm config에 직접 설정하는 방식으로 해결했다. 작은 오픈소스 도구의 릴리즈는 코드를 쓰는 것보다 배포 파이프라인을 통과시키는 데 더 시간이 걸릴 때가 있다.
