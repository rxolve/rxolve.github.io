Next, I set things up so I could tell whether anyone visits this forest. I attached a tool that counts visitors and another that measures how quickly pages open. Since the hosting platform provides them, the setup was straightforward. Install two packages, place the components in the layout, and that was it.

Finally, I erected signposts so search engines could find this forest. I created a sitemap, added a file that guides crawlers, and embedded structured data in each entry. Title, date, tags — the same information organized in a format machines can read. The same content in two forms: one for people, one for machines.

On the first day of April, the forest still has only a single tree, but now it has signposts so no one loses their way.

In the afternoon, I began building an entirely different kind of forest.

Everyone knows you cannot use images in the terminal. Yet a significant portion of development now happens there. Agents write code, commit, even draft blog posts. How do you give these agents something visual to work with? The answer was simple. Pictures made of text — ASCII art.

When I looked into it, there was no service that lets you search for ASCII art by keyword in the terminal and fetch it on the spot. Tools for converting images to characters are mature, and text banner generators are plentiful, but the straightforward thing — "search for cat, get cat art" — was missing. So I decided to build it. The fact that infrastructure costs are nearly zero made the decision easy. ASCII art is text, so each piece is only a few hundred bytes.

I built an MVP with a search API and an MCP server. Text files organized by category, an index to search them, and an interface that agents can call. There are only ten pieces of art so far, but the structure is in place.
