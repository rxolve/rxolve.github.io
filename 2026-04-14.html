주입 지점 두 개

2026-04-14longblack-mcp, longblack-csbot
architecturemcprefactoringtesting

CSBot에는 FastAPI 서버가 있었다. 에이전트가 도구를 호출하면 httpx로 HTTP 요청을 보내고, FastAPI가 받아서 DB를 조회하는 구조였다. HTTP 홉을 없애려면 쿼리와 비즈니스 로직을 독립된 패키지로 꺼내야 했다. longblack-mcp라는 이름으로 함께 설계했다.

단순히 코드를 옮기기만 하면 테스트할 수 없는 패키지가 된다. 평가 시스템에서 프로덕션 DB 대신 SQLite를 넣을 수 있어야 하고, 시각을 CS 요청 시점에 고정할 수 있어야 했다. engine.py에 set_engine을 추가해 엔진을 바깥에서 교체할 수 있게 하고, db/time.py를 새로 만들어 get_now로 현재 시각을 제어할 수 있게 했다. 주입 지점 두 개. 이것만 있으면 패키지를 어디에 붙여도 격리된 테스트를 돌릴 수 있다.

마이그레이션을 마치고 프로덕션에서 에러 없이 도는 것을 확인한 뒤, api/ 디렉토리를 삭제했다. main.py 2,628줄, 클라이언트 두 개, 테스트, Dockerfile. git rm 한 번에 3,558줄이 빠졌다. PR을 올리자 리뷰 봇이 평가 시스템의 격리가 깨졌다고 짚었다. 프로덕션 DB를 그대로 읽으면 결과가 비결정적이 되고, 시간 고정도 풀렸다는 것. 미리 만들어둔 set_engine과 get_now로 고쳤다. SQLite 엔진을 주입하고, before_cursor_execute 리스너로 SQL의 NOW()를 기준 시각 문자열로 바꾼다.

예전에는 테스트용 API 서버를 별도 프로세스로 띄우고 포트가 열리길 기다렸다가, 끝나면 죽여야 했다. 지금은 함수 호출 두 번이면 된다.
